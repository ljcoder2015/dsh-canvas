## 一、产品概述

### 1.1 一句话定义

一个运行在 DeepSeek Harness 上的插件，把项目组织成一张无限画布，画布上的每张文件卡片绑定一个独立的 Agent 会话，取材关系在卡片之间传递数据，最终产出 PPT、网页、文档、图表等任意文件形态。

### 1.2 核心设计理念

**文件即产物，卡片即会话，取材即数据。**

- **文件即产物**：画布上的一切与磁盘一一对应，产物形态由文件证据认定，不需要预先声明“这是 PPT 模式”或“这是网页模式”。
- **卡片即会话**：每张卡片绑定一个独立 Agent 会话，会话只负责当前卡片的产物生成，上下文天然隔离，互不污染。
- **取材即数据**：卡片之间只有一种连线——**取材**。B 取材于 A，表示 B 的产物建立在 A 的产物之上，这是唯一的显式数据通道：Agent 通过它拿上游产物作输入，而非自动感知全画布。

连线的语义被刻意收窄到只剩取样一个方向。改自、接着、对照、批注这些协作语义不再由连线表达，而是交给卡片命名、产物内引用与共享便利贴承载——**能靠约定表达的，就不该变成画布上的结构负担**。

### 1.3 与同类方案的区别

| 维度 | 传统 AI 创作工具 | 本插件 |
|------|----------------|--------|
| 上下文 | 单一长会话，上下文膨胀 | 每张卡片独立会话，按需注入 |
| 产物形态 | 预定义模式 | 文件证据自动认定，可扩展 |
| 协作方式 | 聊天框描述 | 取材关系显式传递数据 |
| Agent 可见范围 | 全部内容 | 仅当前卡片 + 显式引用 |
| 扩展方式 | 加功能分支 | 加形态注册表条目 |


## 二、核心概念

### 2.1 项目（Project）

一个项目对应一张无限画布，底层绑定一个工作区目录。项目是持久化、可分享、可复用的容器。**项目的身份写在目录自己身上**（目录里的板面文件记着它是哪张画布，F1.9），所以这个容器连同它的目录一起被改名、搬家、拷贝或交给别人，都还是同一张画布。

### 2.2 卡片（Card）

画布上的最小创作单元，与磁盘文件一一对应。卡片 id 是画布铸出的 6 位随机字母（座位身份），产物文件路径记在卡片的 `file` 字段上（v1.49 起，详见技术文档 §十一）。卡片绑定的产物可以是单文件（如 `deck.html`），也可以是含 `index.html` 的目录（如站点）。

### 2.3 会话（Session）

每张卡片绑定一个独立的 Agent 会话。会话的 system prompt 注入当前卡片的元信息（路径、形态、项目风格），工具调用只作用于当前卡片绑定的文件。

### 2.4 取材（Source）

卡片之间的唯一有向连线：**B 取材于 A**，即 A 是 B 的上游产物来源。一张卡片可以有多个上游，也可以被多张卡片取材。

取材有两个来源：用户手动连线，以及**自动对账**——产物里真实引用到的素材，反向生成取材边。

取材数据独立于产物文件，作为画布元数据持久化：本机读写的真源是存储领域，同时它也是**随目录走的板面快照**里的一部分（F1.10），于是换成另一台机器打开同一个目录，取材关系跟着回来。

### 2.5 形态（Kind）

产物的类型，由文件证据自动认定。一种形态对应注册表中的一个条目，定义寻址、预览、导出、发布方式。

| F1.9 | 画布身份随目录走 | 一个画布目录**自己记着它是哪张画布**。于是把目录改名、搬到别处、或整个交给同事，重新绑定时认回的是**同一张画布**：座位、取材、便利贴原样在。判据是「记录里那个旧路径还在不在」——**旧路径没了＝目录被搬走了**（认回来）；**旧路径还在＝这是拷出来的一份**（给它一份自己的新身份，否则两个文件夹共用一个板面，在一边删掉卡片另一边也会消失）。没在这台机器上见过的目录（内含板面文件、存储域里没有记录）照它自己的身份收下，所以它从别的机器来也接得住；而第一次绑定一个老目录时**一个字节都不用迁**——没有板面文件就退回「路径摘要」这套老身份，已存在的画布因此原地不动（v1.47） |
| F1.10 | 板面随目录走 | 画布目录里多一份 `.dsh-canvas/board.json`：**这张画布是谁**（画布 id、名字、风格档案）加**板面本身**（卡片与它们的座位、取材边、便利贴）。座位还带一个**只在为真时写**的标记：**这一格生来就没有产物**——它是 F1.11 那条豁免（空座位不算失效）的载体，于是这份豁免也跟着目录走。标准 JSON、排序输出，可读、可 diff、可手改、模型也能直接读；改动板面后写回一次，**内容没变就不写**（不惊动文件监视器、不产生空 diff）。它是**投影不是真源**：本机的读写与命中测试仍走存储领域，写失败只记一行日志（目录只读或沙箱拦下时，板照常可拖可连），而**读不懂的文件绝不覆盖**（可能是手改到一半，也可能是更新格式写的）。跟着走与不跟着走的划线处是**属性归谁**：作品的关系与布局走，`sessionId`（换台机器就是另一个会话）、视图状态这类本机的东西不走。目录里的这份文件认不出卡片的**对话**、也不认视图状态，重建时按文件证据重新认定形态 |
| F1.11 | 清理失效卡片 | 产物已被删除（或改名）的卡片**留在板上**——它可能只是切了分支、也可能你只是想让这一格还在，所以插件从不自动清它，卡片以预览变淡示意（F3.5）。代价是清起来只有选中面板一条路，一张一张确认；板上攒下十几张就是删掉整张画布的动机。现在缩放条上有一枚 **清理失效卡片 (N)**：只在板上真有这种卡时出现（空板上一颗多余的按钮都没有），N 就是实时的张数，点了先问一句再动手。**「失效」在这里只指一件事：产物确实丢了**——探针能把这条路径解析出来、且明确回答没有这个文件，而这张卡也不是「建座时就没有产物」的空卡。所以三样东西**不算**、也不会被清：还没写过产物的空座位（刚落座等着写、位图等着生成、Agent 先落位后写文件，缺产物是**正常状态**而不是丢了文件）、探针答不上来的卡（路径不可解析、沙箱或权限拒绝——答不上来就不许下结论）、以及整个画布目录都读不到时（那时每张卡看起来都缺，而「真没了」与「探针坏了」从这里分辨不出，于是整体拒绝，想清空整张画布请走「移除画布」）。按钮上的 N 与真正会少掉的卡是**同一个集合**，所以清完会说一句实数：确有读不到而被留下的，照实说有几张。清掉的是**卡片**，不是文件：磁盘上的任何东西都不会被删，拿掉一张会连带忘掉它绑定的对话与取材关系——这正是要先问一句的理由（v1.47） |

### 3.3 卡片-会话绑定

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F3.1 | 会话自动创建 | 创建卡片时自动创建独立 Agent 会话 |
| F3.2 | 会话元信息注入 | system prompt 注入卡片路径、形态、项目风格档案 |
| F3.3 | 会话隔离 | 卡片 A 的会话看不到卡片 B 的对话历史和文件内容 |
| F3.4 | 会话持久化 | 对话历史持久化，卡片重开时自动恢复 |
| F3.5 | 会话状态指示 | 卡片上**没有状态点**：运行中由流光说（F3.7），流光不在就是「没事发生」——卡面因此只有名字与产物预览两行信息，**产物确实丢了**的卡片以预览变淡示意。变淡**不是**「这个文件现在读不到」：还没写过产物的空座位（刚落座等着写、位图等着生成）与探针答不上来的卡都照常显示，因为那都不是「丢了」——判据由 Host 给，于是变淡、计数与清理（F1.11）用的是同一个集合。卡片那圈边框是**完整**的：四角都是圆角，包括左右下角——贴齐卡片内缘的两层各自那一侧给的是**同心**圆角，否则它们的不透明底色会在圆角处把边框盖掉一段（v1.34） |
| F3.6 | 卡片切换 | 卡片胶囊上的「对话」按钮把主区域切到该卡片会话（对话页面本身不再有画布卡片标签页，见[技术文档 §8](./DeepSeek-Harness-Canvas-技术文档.md)） |
| F3.7 | 生成中反馈 | 会话运行中时卡片亮起**流光**：一道斜切光带从左扫到右、匀速不停顿，画在独立子层上盖住整卡——卡片自身不能裁剪（取材端口悬在卡外）；名字与预览照常显示，光的往复就是「正在产出」的整句话。卡面只微亮一档、**边框不变色**（边框归悬停与选中）。回合结束流光即停，画布重读产物摘要、卡面回显新产物。**「减少动态效果」下不熄灭**：同一条光带照扫，只把动感降下来——光在动是这张卡唯一的进行中信号，停摆的光与「卡住」无从区分（v1.19 / v1.21） |
| F3.8 | 双击全屏预览 | 双击卡片全屏展示产物内容，**弹窗就是整块画布大小**（与画布区同宽同高、不留边距、不切角）；头部只有产物名、形态、关闭 ×，**文本节点另有一条「预览 / 编辑」单选组**（F3.12）。按形态取预览器——Markdown 渲染、图片 / 视频、HTML 与 Deck 沙箱 iframe、CSV / JSON 表格、其余纯文本兜底；**加一种形态 = 加一个文件 + 注册表 import 一行**，弹窗与控制带一行都不用改。产物全文经通道传输，过大时截断或如实提示上限；**预览里的链接**（v1.36）——页内锚点原地跳、绝对地址真开新窗、相对地址拦下并显说明条（沙箱里的相对基准是宿主页面）（v1.6 / v1.23 / v1.24 / v1.42） |
| F3.9 | 提示词回填 | 控制带的输入框与 ⤢ 全屏弹窗**共用同一份草稿**（一盒两尺寸，见 F3.11）：两者在用户未编辑时都显示该卡片**最近一条自己发出的消息**（逐字保留换行），冷会话（本页从未打开过）照读；插件注入的取材上下文不算用户的话、不回填。用户键入的草稿优先于回填、按卡片各自保留（v1.9） |
| F3.10 | 操作胶囊收敛 | 选中卡片上方的动作胶囊只留**没有其它入口的动作**：对话、**手动输入**（文本节点专有，见 F3.13）、导出、从画布移除。「打开」删除——产物展示归双击全屏预览（F3.8）；「建立取材」删除——取材已由卡片两侧端口与控制带 ⊕ 菜单覆盖，胶囊不再放第二扇更弱的门（v1.10） |
| F3.11 | 卡片控制带 | 选中卡片下方是一条**控制带**：提示词**输入框**（⌘/Ctrl+Enter 发送，空稿禁用发送；`@` 引用画成标签，F3.18）与取材 chips、⊕ 引入入口、**⤢ 放大输入框**、模型席位一行排开。**右下角有一颗把手，拖它就是把这条带子放大**（宽与输入框的高一起走）：放大的只是**空间**——字号、行高、内边距、圆角与那三行结构一律照旧（放大态用的是同一个输入框、同一套字，没有另一副更大的），多出来的地方**只归输入框**；**锚在卡片中心**——放大时左右两侧对称地长，输入区始终与节点居中对齐（代价是右下角那颗把手只吃得到半个位移，所以宽按两倍走，才跟得住光标）。往回拖缩得回去，按一下不移动则什么都不改；拖出来的大小**按卡记着**（本机内存，不落盘、刷新回默认）。**右上角那颗 ⤢ 打开的是同一个控制台换了个壳**：里面还是那三行（材料行 + 输入框 + 底栏），输入框的字号/行高/内边距/圆角与行内逐字相同、草稿也是同一份，只是容器更高、输入框占得更多。**两处按钮各管各的壳**：带子右上角那颗是 **⤢ 放大输入框**，弹窗**头部右上角**那颗是 **⤡ 缩小输入框**——它开合的是这个弹窗，所以站在壳的头上、不混进那三行里（材料行与行内逐项相同，一颗多余的按钮都不多）；Esc 与点遮罩同样可以退。卡片上没有「还没有消息。」一类的状态文字、**也没有状态点**——进度由流光（F3.7）说、产物由卡面预览说；发送入口是条内输入框、⤢ 弹窗与「对话」胶囊三条（v1.45） |
| F3.12 | 文本就地编辑 | 文本节点（Markdown，以及按扩展名分不出形态的纯文本文件）在预览弹窗里可以**手动改**。切换是头部那条**单选组**（预览 / 编辑并排，选中的一半是实心拇指——当前在哪一面是看出来的，不是从按钮上的字反推的；方向键跟着选中态走、到头不绕回；**焦点进编辑器后方向键归光标**）。切到编辑面就是整块画布大小的等宽编辑区。写盘两条路：**打字停手即自动落盘**，以及 ⌘/Ctrl+S 或头部「保存」的**立刻落盘**（后者写完重读并刷新画布；两条路都交回预览面）。**预览面渲染的是缓冲区而不是磁盘**——改完字切过去看到的就是刚打的那一段，否则会让人以为白改了；**未保存时**头部挂「未保存」标记，此时关闭先问一句，草稿在两面之间来回切换时留在原地——**不静默丢字**。**读不全的产物不给编辑**：编辑器整篇写回，会把没读到的那部分一起覆盖。**写入被拒**时不说原生错误、也不无限重试：重试也不会好的**暂停自动保存**并把「重试」交给用户，一时性的按退避重试；错误条主句说人话、原生错误降为细节行（v1.26–v1.29） |
| F3.13 | 手动输入 | 胶囊在「对话」之后多一枚**手动输入**，只在文本节点上出现（判定与 F3.12 同一份；文件夹、图片、Deck、应用一律不给——编辑器整篇写回，给它们一枚编辑钮就是把文件改成文本）。点它打开**同一个**预览弹窗（F3.8），只是**直接落在编辑面**：手动写这一篇与让模型写这一篇，是同一张产物的两条路（v1.26） |
| F3.14 | 预览里的元素选择 | HTML 家族的**全屏预览**头部多一枚**元素选择**开关。**按下即进入选择模式**：**这一页暂时变成只读的**——照浏览器调试工具的元素选择那套，鼠标移到哪儿就圈住哪儿，页面自己的悬停、按钮、输入与文字选择一概收不到这一下；鼠标在整页范围内统一是十字。指针底下的元素**当场亮框**并写出它的记号。**单击即选中**，这一击**不落到页面自己的按钮或链接上**，随即在元素正下方弹出**提示词框**：框里已嵌着产物文件、节点记号、选择器路径与**这个节点自己的源码**，以「改动要求：」收尾，光标落在末尾且那一行**滚进可视区**，等用户接着写。**给的是定位不是补丁**——序列化结果与文件原文未必逐字相同，模型照路径自己去文件里落刀。写完后发送走与画布输入框**同一条**通道，交给这张卡自己的会话去改文件。说明条**一律浮在帧上、不占排版位**——「正在选元素」那条随模式在单击那一刻消失，发送之后的回话也一样浮着；它们若排在流里，出现或消失的那一瞬就会把整帧顶走一整条（实测 43px），而圈与框的位置是拿帧的坐标画的。**选元素的时候页面还能滚**（不然下半页的元素够不着），**但一笔选定、框开着之后，页面连动都不动**：滚轮与滚动位置一起冻住——用户正在写"改这一段"，页面在底下滑走，圈住的位置就不再是他在说的那一段了。**发送之后框不收**：圈上亮起与卡片**同一道流光**（光在动 = 正在产出），框留在元素旁等产物真的变，产物一更新才自己收起（用户在这期间又写了下一句则留着，不替他丢那句话）。**圈与框一直钉在这个元素上**：帧的位置是**活的量**——手里攥着一笔时持续重测（界面一变量一遍、帧自己的大小变了量一遍、窗口缩放量一遍），帧被谁挪走，圈与框都跟着它走，绝不从元素上错开。**关掉预览再打开，这一笔摆回原样**（圈、框与草稿都在）——它按卡记着、比弹窗活得久；**改动已经落地、或用户明确关掉（× / Esc），就不再摆回来**。手里攥着一笔时工具按钮按不动：重新选会把这正在改的一笔顶掉。页面里自己的滚动条在选元素时滚不动（整块预览被一层透明层盖住）——选不到的元素先退出模式滚过去，再进来选（v1.39 / v1.44） |
| F3.17 | 改动落到本卡产物 | **同一个卡片的多轮对话只产出这一份产物**：凡涉及改动的回合一律**覆盖本卡产物**，不新建卡片、不留 `-v2` / `-copy` 这类第二份让人挑；「再改一下 / 换成… / 加上…」是**修订**，不是新产物——对话本该收敛到一份越改越好的东西，一轮一个新文件等于把用户手里的线索打散，画布上还多出一张他本来只是想改一改的卡。**产物是站点 / 应用的入口文件时**，同目录的那一族文件就属于**同一份产物**（F5.4），照常编辑；越界的只有「另起一份交付物」。**建卡是用户的动作**：卡片由用户拖出节点或明确要求产生，会话不会因为「想写点什么」而顺手建一张（`canvas_create_on_board` 同理，不拿它回答一次改动）；只有用户明确要一份**独立**的交付物时，模型才把这句话说出来、由用户去建——既不悄悄分叉，也不拿别的东西盖掉本卡产物。规则写进卡片会话的系统提示词（F3.2），**没有机械强制**：插件不禁止写别的文件（站点、应用本来就多文件），管住的是「另起交付物」这一件事（v1.46） |
| F3.18 | 提示词里的引用标签 | 输入框里的 `@文件` 记号**画成一枚标签**——图标（或缩略图）+ 文件名 + 可选徽标，整体是一枚**不可分隔的原子**：Backspace / Delete 在标签边界上删的是**这一枚引用**（不是它的一个字符），标签内部没有光标可落，复制 / 剪切在剪贴板里还原成 `@路径`，粘贴只取纯文本（富文本带进来的那棵 DOM 正是「内容就是值」这条边界最容易被撕开的地方）。**标签只是画上去的**：它序列化出去的是**它自己那串字符**（`@a.ts` / `@"my brief.md"` / `@hero.png <point>420 380</point>`），不是从路径重新拼的一份——宿主记号有三种形态，反推就可能把发出去的提示词改掉一个字节；「拼回去逐字节等于原文」由单测与真浏览器判据共同钉住。**类型按扩展名定**（判据只有一份、写在路径里，卡片离开画布也读得到）：`code` / `image` / `video` / `audio` 指一份**文件**，`mark` / `region` 指一张图上的**一个点或一个框**（坐标归一化到 0–999，与图像模型同一套刻度；紧跟在文件记号后面的 `<point>` / `<bbox>` 并进**同一枚**标签——「这张图上的这个点」是一件事，不是两件；坐标还没有界面产生，契约先钉在解析器里，等图像预览器有了圈选）。**标签写文件名，不写序号**：本插件的锚点就是路径，模型照它自己去读那一份文件，视觉内容不走第二条通道——两枚同名图片因此在提示词里也分得清谁是谁。**`@` 候选菜单**：光标前打 `@` 就浮出候选——这张卡已有的取材来源在前（关系是板上画着的）、画布其余卡片在后，各截 8 枚，键盘上下 / 回车选中、Esc 收起；媒体类候选与标签都画缩略图（分批读产物，取不到退回类型图标——缩略图是锦上添花，不是引用的前提），**缩略图回来不端走光标**：草稿没变、只是事实变富时，重画前后先量后画，光标与选区原样还回去。两处落点（控制带与元素选择的提示词框）是同一个组件；**行高是判据**——一枚标签（含缩略图）不许把正文那一行撑开，否则插进一句话中间就把整段的行距改了（v1.48） |

### 3.4 取材关系

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F4.1 | 取材关系 | 卡片之间唯一的连线类型：B 取材于 A。有向、可多重（一张卡片可有多个上游，也可被多张卡片取材） |
| F4.2 | 取材建立 | **从锚点拖线**：按住卡片侧边的端口拖出去，拖拽中的线从**锚点（端口圆心）**起笔、终点跟随指针，样式为**细线、无箭头**——它还不是一条关系，只是一个还没落地的动作。松手落在另一张卡片的端口上即直接建立（只需定方向，不需要选类型）；落在空白处则就地弹出「新增节点」弹窗（F4.8） |
| F4.3 | 取材持久化 | 取材数据作为画布元数据独立存储、不随卡片走。存储键由两端卡片 id 转义拼成——卡片 id 是路径、带点带杠，而存储介质对键有更严的字符集要求，不安全的键会在写盘时被整体拒绝。**v1.47 起同时写进目录里的板面快照**（F1.10）：本机真源仍是存储领域，那份快照负责让取材关系跟着目录走，所以换台机器打开同一个目录时边还在（从文件导入的边要过与手绘连线**同一道**校验，自己成环、重复、端点不在板上的边一律丢掉） |
| F4.4 | 取材可视化 | 落定的取材线与**拖拽中的线同款**：细线、实线、无箭头、breeze 色（F4.2）——线上没有第二个样子，选中卡片时只把不透明度提亮一档。**线不可交互**：整层不接指针事件，线只负责看，永不拦截跨越它的拖拽（解除取材走 chip 上的删除钮，F4.9；不在画布上点线）（v1.18） |
| F4.5 | 自动对账 | 产物中真实引用的素材自动生成取材边（HTML 里的 `src`、Markdown 里的图片链接等） |
| F4.6 | 上游链排布 | 按取材链分层：上游在左、下游在右，同层对齐。三种策略——**按深度成列**、**纯网格**、**整理**（链上的卡按链排、散卡在下方网格收拢），Agent 工具可指定。**画布左下角的「自动排版」按钮**走同一条通道、用整理策略（v1.22） |
| F4.7 | 上游追溯 | 查看当前卡片的完整上游链（含间接上游），以及取材于它的下游卡片 |
| F4.8 | 空白落笔建卡 | 拖线放到**空白处**不再直接作废：放手点就地弹出「新增节点」弹窗（应用 / 文本 / 图片 / 矢量图片，与 dock 新增同一份菜单），点一种形态即**当场建卡并连线**——新卡片按放手点落位，让它的端口正好接住刚才的线头，于是细线不是「跳」到卡片上、而是就地变成取材边；弹层向屏上空间更大的那一侧张开。**点弹层以外、按 Esc、或手松在画布之外，都取消这一笔**——不留卡片也不留线 |
| F4.9 | 取材解除 | 控制带里每枚取材 chip 的**右上角挂一枚删除钮**：一条 chip 就是一条**直接**取材边，点删除即删掉这条关系，画布与存储同步退场。chips 只列直接边——**间接**上游是更上面某张卡的关系、删无可删，不进 chips（这也与取材通道一致：材料本就只取上一级，F5.8）；chip 加大一号，卡片不裁剪，角标探出上缘（v1.20） |

### 3.5 取材作为输入通道

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F5.1 | 拉模式注入 | Agent 或用户主动调用工具获取上游材料，分**产物摘要**与**上游产物文件引用**两条路（v1.37） |
| F5.2 | 摘要注入 | 注入内容为文件路径 + 内容摘要 + 关键结构，非全文。与文件引用**并列而非回落**：文件引用说材料在哪、模型按需去读；摘要把材料立刻摆到眼前，页面级摘要仍由它承担（v1.37） |
| F5.3 | 显式引用 | **v1.37 落地**：卡片 ⊕ 菜单「引用上游产物文件」——用户显式把上游产物**以路径**提交给本卡会话，写法就是 Harness 自己的 `@file`（与宿主实现逐字节一致）。**不复制内容**：注入的只是一组名字加一句「这是引用不是内容」，读不读、读哪一段由模型自己决定 |
| F5.4 | 引用可达性 | **v1.37 落地**：名字必须**真的解析得到**——引用写的是卡片的产物文件路径（记录在卡片的 `file` 字段上，v1.49），产物落在画布根下的同一个位置，模型读一下就拿到材料。**卡片是文件不是目录**（站点 / 应用这类目录形态的卡片坐落其入口文件）：报名字时一律按文件形态给，不推目录 |
| F5.5 | 引用如实 | **v1.37 落地**：工具如实回报每一项的名字、路径、形态、存在性与大小（没写盘就标为不存在，不编大小），并把**语法写不出来的路径**（含引号或控制字符）**上报而非悄悄丢掉**；注入消息随「插件来源」标记持久落盘，事后可查 |
| F5.6 | 变更通知 | 上游产物被改后，向**存活**的下游会话注入一条变更通知；已关闭的卡片没有会变陈旧的上下文，空闲会话**不被后台写入唤醒** |
| F5.7 | 响应策略 | 配置项三档：**不通知** / 只报「上游变了」/ 连新摘要一起带上（省掉一次工具调用）。**注意分工（v1.37）**：变更通知这一路走**产物摘要**——它要的是「立刻把材料摆到眼前」；文件引用不需要通知，因为路径指向的**正是那个文件**，上游怎么改它都指得对，重新取用只需再报一次名字 |
| F5.8 | 取材只取上一级 | **v1.46**：一张卡片能取用的材料**只有它的直接上游**（上一级），不做穿透引用——这是三条通道共用的一条规矩：每轮提示里的取材块、`canvas_read_sources` 的摘要、`canvas_reference_files` 的名字，一律只报本卡自己那几条边指向的产物。理由：链要**折**不要**摊**——产物本应把上游材料消化进自己那一份，把祖父的产物塞进孙子的提示词，花的是上下文、拆的是画布自己画出来的那条流水线；而「本产物建立在它之上」这句话，隔一层就不成立了。**能看的仍然看得到**：F4.7 的取材链照旧报全链（含间接），`canvas_get_sources` 拿链、`canvas_read_card` 读其中任一份，属实**明确去取**，不是默认送到。配置项 `sourceDepth` 自此只作用于链视图，不作用于取材 |

**两条通道，一条边**（v1.37）：同一条取材边有两种可取用的材料，**各司其职、互不替代**。**为什么底层是文件而不是会话**：边指向的那份产物**可能是手动新建的**——没有任何会话生成过它；也可能是**某次会话产物被二次编辑后的版本**——内容已经不等于那次会话的记录。拿会话去代理产物，这两种情况下都会**指错**（把「谁生成过」当成了「这份东西是什么」）；文件引用不问来历，只认磁盘上那一份。**文件引用是指针**——它把上游产物的路径交给新会话，内容一个字都不复制，因此**不会失效**、**不占预算**、**不被截断**、**没有缓存与失效时机要定义**；代价是模型要自己读（多一次工具调用），以及**可能不读**——所以引用块里写明「这是引用不是内容，没读过的文件不要描述」。**产物摘要是快照**——把材料的一份有界摘要**立刻**摆进上下文，零调用，但有损、有预算、每次现算。选哪条按「下游现在要的是什么」定：**知道有哪些材料、按需取用 ⇒ 文件引用**（这是默认）；**立刻需要那份材料在场 ⇒ 摘要**。**唯一不许含混的是「什么都没给」**：没有上游是事实，路径写不出来则**明说写不出来**——一条正文为空的注入消息会消失，模型会以为这张卡根本没有上游，那比「说了、但一个也没命名成功」更糟。

### 3.6 Agent 跨卡片工具集

工具名一律用 `canvas_` 前缀 + 下划线分隔（如 `canvas_read_card`）：名字会作为工具名发给模型供应商，字符集被限死，带 `.` 的名字会被直接拒绝。（[技术文档 §12](./DeepSeek-Harness-Canvas-技术文档.md) 的第 1 项开放项由此关闭。）

| 工具名 | 功能 | 参数 |
|--------|------|------|
| `canvas_read_card` | 读取指定卡片产物摘要 | `cardId` |
| `canvas_read_sources` | 读取取材来源（直接上游产物）的产物摘要；只取上一级，F5.8 | 无 |
| `canvas_reference_files` | 把取材来源（直接上游产物）以**文件引用**提交给本卡会话：不复制内容，模型自己按需去读；只报上一级，F5.8（v1.37） | 无 |
| `canvas_link_source` | 声明本卡片取材于另一张卡片 | `sourceCardId` |
| `canvas_get_sources` | 获取当前卡片的取材链（直接上游、间接上游、下游） | 无 |
| `canvas_inject_card` | 将指定卡片产物注入当前会话 | `cardId, mode` |
| `canvas_read_board` | 读取画布当前座次与取材边 | 无 |
| `canvas_arrange_on_board` | 按取材链语义化摆位 | `strategy` |
| `canvas_create_on_board` | 创建便签或卡片 | `type, content` |
| `canvas_organize_board` | 归纳收纳 | 无 |
| `canvas_link_source_on_board` | 画取材线 | `from, to` |
| `canvas_generate_image` | 生图 | `prompt, cardId` |
| `canvas_export` | 导出产物 | `cardId, format` |
| `canvas_publish` | 发布产物 | `cardId` |

**两类工具，两套「我是谁」**（v1.31 修订）：前六项以**卡片**为作用域——调用方身份从会话解析，解析不出就直说「请先打开这张卡片的对话」，不猜、也不退让；其余八项以**画布**为作用域，取项目分两级：**用户当前打开的画布**优先，全局为空时**卡片会话回落到这张卡片所属的画布**——卡片会话是唯一「项目确定」的地方，对它回「没有画布」等于对一个明明在画布里的会话说没有画布；两级都取不到才拒绝。所以同一个「读取画布座次」，在画布上的卡片对话里能跑，在无关的普通会话里会被拒——这是设计，不是故障。

## 五、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 取材注入模式 | 拉模式优先 | 会话隔离干净，上下文可控，避免膨胀 |
| 会话可见范围 | 仅当前卡片 + 显式引用 | 防止上下文污染，聚焦单一产物 |
| 连线范畴 | 只保留「取材」一种 | 语义被收窄后，画布结构不会随协作话术膨胀；其余语义交给命名、产物内引用与便利贴 |
| 形态认定 | 文件证据自动认定 | 通用性自然获得，加形态不改分支 |
| 卡片 id | 文件路径 | 与文件系统一一对应，无需额外映射 |
| 取材存储 | 画布元数据独立于产物文件 | 文件系统不擅长表达跨文件依赖 |
| 引用方式 | 快照式 | 可追溯，避免实时同步的复杂性 |
| 双端形态 | 双端插件（Host Cordis + Client Web） | 画布是重交互 UI，必须跑在浏览器半；Host 半持有文件、会话与工具 |
| 双端通信 | 一份 wire 契约，三处引用 | Host manifest 与 Client 贡献指向同一 descriptor 数组，结构上不可能漂移 |
| 数据落点 | 存储领域（domain）而非自建文件 | 复用后端路由、版本校验、写链与 `domain/changed` 通知 |
| 画布跟着目录走（v1.47） | 存储领域**加**一份随目录走的板面投影（F1.9/F1.10） | 只存存储域时「画布＝这个文件夹」只在同一台机器上成立：改名即换一张、换机器即空板。反过来只存文件，就要自建原子写、并发串行与版本迁移，把存储域白给的 schema 校验与写链再写一遍。**分工是「谁是真源」与「属性归谁」**：本机读写仍走存储域（投影可以慢一拍、可以失败），作品的关系与布局跟目录走、本机态（会话绑定、视图）留下 |
| 会话隔离手段 | 工具注册作用域 + 可见性过滤 | 把隔离做成结构约束，而不是提示词约定 |
| 文件访问 | 统一走 `ctx.fs` seam | 自带版本守卫、沙箱策略与写前 waterfall，直接可用 |
| 画布承载席位 | 右栏停靠面为主、全屏覆盖层为辅 | Web Client 主区域属于对话，不自造席位 |
| 产物预览 | 复用右栏 tab 类型注册表 | 按资源地址认领，`extension` 档压过内置查看器，卸载即恢复 |
| 卡片会话的模型 | 自建 agent 时补 `agentOptions`，会话选择经 `sessionController.selectModel` 装回 | 卡片会话不走控制器的组装路径，缺前者装配即失败、缺后者跨重载丢选择；而选择策略本身仍归控制器 |
| 模型选择器写在哪 | 会话级（宿主投影）为真源，节点类型记忆只作"新会话继承" | 会话一旦自己选过就以会话为准，跨节点类型的记忆不覆盖已用过的卡片 |
| 卡片会话的工具 | 从部署的 agent preset 组装（`ctx.agentPresets.mount` 于工厂 `setup`） | Web 面已把面向模型的文件工具行从宿主组装移出、改由 preset 提供；自建会话不加入就一个写盘工具都没有，而产物只能靠普通文件工具写出来 |

## 六、产品边界

### 做什么

- 通用文件产物的创作与管理
- 卡片级会话隔离与取材驱动协作
- 任意形态的产物生成（PPT、网页、文档、图表等）

### 不做什么

- 不做实时多人协作编辑
- 不做文件版本控制系统（依赖底层文件系统）
- 不做独立的模型服务（复用 Harness 模型适配层）
- 不做重型渲染引擎（预览依赖浏览器能力）
- 不做通用关系图谱／语义网络（连线只有取材一种，其余协作语义不由结构承载）
